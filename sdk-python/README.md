# veriport

Python client for the [Veriport API](https://veriport.io/docs): EU VAT number validation on VIES with a dated cache, EU VAT rates dated and sourced per row, IBAN validation from the SWIFT registry, French company data by SIREN/SIRET. One dependency (`httpx`), sync and async, Python 3.9+.

It also ships the **offline** parts of the checks (MIT): the structure of the 28 EU VAT number formats and the full IBAN check (characters, country, length, ISO 7064 mod 97-10, BBAN pattern, bank and branch identifiers, SEPA flag) for the 88 countries of the registry, so that an impossible number never costs a call. The tables are generated from the same source the API uses.

```sh
pip install veriport
```

## One call

```python
import os
from veriport import Veriport

vp = Veriport(api_key=os.environ.get("VERIPORT_KEY"))  # optional for the first 20 calls a day

r = vp.validate_vat("DE136695976")
print(r["valid"], r["source"]["kind"], r["source"]["stale"])  # True live False

iban = vp.validate_iban("DE89 3704 0044 0532 0130 00")
print(iban["valid"], iban["bankIdentifier"], iban["sepa"])

fr = vp.vat_rate("FR")
print(fr["standard"], fr["verifiedOn"], fr["sources"])

company = vp.fr_company("356000000")
print(company["name"], company["status"], company["source"]["primary"])
```

Any operation of the [OpenAPI document](https://veriport.io/openapi.json): `vp.call("GET", "/vat/rates", params={"category": "ebooks"})`. Async: `AsyncVeriport` with the same methods, awaited.

## E-invoices

```python
from pathlib import Path

# invoice dict → XRechnung, ZUGFeRD / Factur-X PDF or Peppol BIS (20 calls; a retry with the same key is not charged twice)
f = vp.create_einvoice({"format": "zugferd", **invoice}, idempotency_key=invoice["number"])
Path(f.filename or "invoice.pdf").write_bytes(f.content)
print(f.validation)  # "valid; profile=en16931; errors=0; warnings=0"

# any e-invoice (XML text, or the bytes of a hybrid PDF) → the official verdict (5 calls; works without a key)
report = vp.validate_einvoice(Path("received.xml").read_text())
for e in report["errors"]:
    print(e["rule"], e["path"], e["message"])

# a received e-invoice → the same invoice dict plus what it leaves out; as_="pdf" gives a readable copy
parsed = vp.parse_einvoice(Path("received.pdf").read_bytes())
print(parsed["invoice"]["number"], parsed["notInJson"])
```

A refusal raises `VeriportError`: `e.code == "einvoice_unsupported"` with `e.feature` and `e.unsupported`, or `"einvoice_invalid"` with `e.violations`.

## Offline first, API second

```python
from veriport import Veriport, check_vat, check_iban, check_vat_structure, validate_iban_offline

vp = Veriport(api_key=os.environ.get("VERIPORT_KEY"))

vat = check_vat("DE 136 695 976", client=vp, requester="FR40303265045")
# vat["kind"] == "structure_only" when the string cannot be a VAT number (no call made)
# vat["kind"] == "api" with vat["answer"] (valid, name, consultationNumber, source) otherwise

iban = check_iban("DE89 3704 0044 0532 0130 00", client=vp)
# iban["offline"] is the full local check; iban["answer"] the API's answer with the registry date

check_vat_structure("FR40303265045").valid        # True (structure only)
validate_iban_offline("GB29 NWBK 6016 1331 9268 19").bank_identifier  # "NWBK"
```

## Errors

Every non-2xx answer is an RFC 9457 problem document, raised as `VeriportError` with the stable `code`:

```python
from veriport import VeriportError

try:
    vp.validate_vat("IT00743110157")
except VeriportError as e:
    if e.code == "vies_unavailable":
        ...  # no cached answer: retry in e.retry_after seconds
    if e.code == "quota_exceeded":
        ...  # https://veriport.io/pricing
```

`vp.last` holds the budget headers of the last answer (`RateLimit-Limit`, `RateLimit-Remaining`, `X-Quota-Remaining`, `X-Tier`).

## What the answers mean

- A VAT answer carries its provenance: `source.kind` is `live`, `cache` or `structure_only`; `source.stale` is true whenever VIES did not answer during the request. A cached answer is evidence that the number was valid on `source.checkedAt`, not today.
- `consultationNumber` is returned on the paid tiers when you pass your own VAT number as `requester`: the reference a tax audit accepts.
- An IBAN that passes is well formed; existence and ownership of the account are the bank's knowledge.
- Rates rows carry `verifiedOn` and `sources`: the day each row was last read and where.
